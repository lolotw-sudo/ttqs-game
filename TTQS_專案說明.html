02 · 緣起與痛點
01.

為什麼
會做這個？

學院要參加勞動部的 TTQS 訓練品質評核，需要上傳 19 項指標的佐證檔案。我想「幫自己整理就好」，結果發現「同系老師也能用」，再後來——「其他系應該也都用得到」。一個自救的小工具，意外長成了一個專案。

PAIN · 01

培訓師根本不知道什麼叫「佐證」

TTQS 有 19 項指標，每項對應不同的佐證資料，規則並不直觀。我跟同系老師說「給我課程設計的資料」，他們隨便丟一份「課程表」過來；我得花時間判斷：這是指標 6還是指標 9？有時連我都不確定。

我就像一台「TTQS 指標翻譯機」，老師丟檔案進來,我要逐一辨認它屬於哪個指標。
PAIN · 02

同一份資料對應好幾個指標

最尷尬的情況：一份「課程表」可能同時對應 指標 2 訓練政策、指標 6 課程設計、指標 10 訓練管理。我跟老師說「能不能再給我一份課程表」,老師心想:「同一份東西為什麼要兩份?」

在老師眼裡,我是個「貪心的檔案怪獸」。但不收齊,評鑑就會說「佐證資料不足」。
PAIN · 03

最痛苦的是,手動彙整這件事本身

收到檔案後,我得改檔名、判斷指標、檢查重複、更新紀錄、整理資料夾……50 份檔案花了 30 小時,而且這還要一邊開課。最糟的是——如果每年都要評鑑,那我每年都要重複一遍嗎?

整理檔案時我就在想:「有沒有辦法讓電腦自動做這些事?」答案是有的——我就自己寫了一個。
Before · 手動流程

30 小時 / 50 份檔案

  1. 老師丟來的檔案,檔名通常很隨意
  2. 看內容,判斷「這是指標幾」
  3. 把檔名改成統一格式
  4. 檢查重複檔案、版本差異
  5. 更新紀錄、整理資料夾
  6. 每年評鑑重複一次,無限循環
→
After · 自動化 + 遊戲化

幾分鐘 / 一鍵下載

  1. 老師拖入檔案到「上傳精靈」
  2. 系統自動判斷對應指標
  3. 系統自動檢查重複與版本
  4. 系統自動正規化檔名
  5. 自動生成 CSV 報表 + ZIP 打包
  6. 老師看到積分升級,主動上傳
03 · 技術架構

無編譯前端,
無伺服器後端。

單一 HTML 入口,瀏覽器內即時編譯 JSX;Firebase 提供即時資料庫、檔案儲存與匿名驗證,GitHub Pages 負責靜態托管。沒有 Webpack、沒有 Vite、沒有 Node 伺服器,卻有完整的多人即時協作。

Role全程開發 / bug 修復 / 重構

05 · 為什麼 CP 值超高

從第一天起,
就是與 AI 並肩工作。

不是「先手動做、再用 AI 優化」,而是「直接用 AI 設計、開發、測試、部署」。最後得到的結果是——

✦ DEV · 開發效率

從想法到上線,1–2 週。

  • 無編譯,直接 HTML + JSX 開發
  • 零伺服器成本,Firebase 免費方案即可
  • GitHub Pages 自動部署,無維護負擔
  • AI 從架構到 debug,全鏈路覆蓋
✦ OPS · 工作效率提升

把「我判斷」交給「系統判斷」。

  • 佐證彙整從手動 → 自動
  • 指標判斷從我 → 系統
  • 報表生成從手做 → 一鍵下載
  • 老師上傳從被動追 → 主動提供
✦ INNO · AI 驅動創新

五個 AI,各司其職。

  • 架構設計:AI 幫我想清楚遊戲化激發動機
  • 快速實現:Claude Code 數小時即可成形
  • 內容精準:多 AI 交叉驗證 TTQS 指標
  • 視覺創意:Claude Design 確立風格語彙
✦ VALUE · 工作中的實際價值

不只省時,還能持續長大。

  • 減少重複:自動化 50 份檔案的彙整流程
  • 提升協作:多人即時同步,不用傳檔
  • 動機激發:遊戲化讓老師樂意提供
  • 可持續擴展:架構簡單,新功能易疊加
